# Security assumptions

- Browser authentication is an HttpOnly cookie, `OpsFlow.Auth`, `SameSite=Lax`. `Secure` follows the request in Development and is always on outside Development. Tokens are not stored in `localStorage`.
- State-changing controller actions require an antiforgery token in `X-XSRF-TOKEN`. The token is kept in memory by the SPA. The antiforgery cookie itself is HttpOnly. The token is bound to the current principal, so the SPA requests a new token after login and discards it on logout.
- Data-protection keys are on disk in development and in a private blob when `DataProtection__BlobUri` is set, so container restarts and extra API replicas can decrypt the same cookies.
- Login defaults to 10 requests per minute per IP (`RateLimiting:LoginPermitLimit`). Writes default to 120 per minute per user (`RateLimiting:WritePermitLimit`). Both limiters are in-process. With more than one API replica, the effective limit is the per-instance limit times the replica count.
- Request bodies are capped around 12 MB. Attachments are capped at 10 MB and 5 files, with an extension and magic-byte allow-list. Downloads use `Content-Disposition: attachment` and `X-Content-Type-Options: nosniff`. Storage keys are server-generated and rejected if they contain `..`. Type checks are not malware scanning. Scanning is out of scope.
- If the blob upload succeeds and the database insert fails, the object is deleted. If the database delete succeeds and the blob delete fails, the object can remain and is logged. There is no anonymous blob access in the Bicep container definition.
- Problem details hide exception details outside Development. Logs should not contain passwords, cookies, connection strings, or file bytes. Audit summaries are capped at 500 characters. Nothing in the API updates or deletes audit rows. Those rows are ordinary SQL data and can be changed by someone with database access, so they are not tamper-proof.
- Azure SQL firewall rules come from an explicit IP list. The template does not open `0.0.0.0` to the internet. `allowAzureServices` defaults to false. Container Apps still need either that switch, their outbound IPs, or private networking before they can connect. Private endpoints are not generated in this first template.
- Production CORS is unnecessary when the API serves the SPA. The Vite dev server proxies `/api`, so cookies stay same-origin.
